# Bootstrap System Design

初始化由入口、版本化资源包、初始化执行器和结果报告协作完成。入口将用户意图转换为目标项目及操作选择；资源包定义固定目录、骨架文件、完整协议与版本；执行器检查目标并产生确定的文件变化；结果报告供人和 Agent 判断完成范围及后续选择。

### 资源与计划

固定骨架由资源清单驱动，不由模型临时推导。资源包保存每份文件的完整内容与一致性校验值，执行前验证资源完整性及协议版本一致性。导出的协议来自 MukiDoc 项目维护的权威协议，发行内容变化时需要提升版本，防止同一个版本代表不同规则。

执行器先检查所有受管路径的类型，区分缺失目录、缺失文件、已有文件与路径冲突。受管位置出现符号链接或类型不匹配时报告冲突，不沿链接改写其他位置。检查完成后形成创建、保留和替换计划；预览只返回计划。

固定目录可以为空，以保留标记随版本控制保存。已有文件默认不写入；缺失文件按模板建立。非骨架内容不受管理，也不因为目录不在清单内而被删除。

### 协议状态

协议判断同时使用版本与完整内容比较：

| 状态 | 默认动作 | 替换条件 |
|---|---|---|
| 缺失 | 安装内置协议 | 无需覆盖 |
| 内容一致 | 保留 | 不需要更新 |
| 可识别旧版 | 保留并提示版本更新 | 明确同意更新 |
| 同版内容不同 | 保留并指出本地差异 | 明确同意完整替换 |
| 无唯一版本 | 保留，不猜测 | 明确同意完整替换 |
| 比内置版本更新 | 保留 | 当前执行器不降级 |

版本按数值比较。版本判断只针对当前资源包，不查询或宣称全局最新版本。

### 替换与保留

需要确认的协议可以先保留，其余骨架正常补齐。入口检查实际差异并获得用户决定；授权与待替换文件的内容指纹关联。执行前再次核对指纹，发现变化就停止替换，要求重新检查变化。

替换先写出唯一命名的原文件备份，再将完整新协议写入临时文件，最后替换目标。备份保留原字节，不能用新的初始化覆盖旧备份。明确授权由调用方负责；执行器的显式替换参数表示调用方已完成确认，不负责对话。

目录与新文件创建不是全局事务。实际写入遇到 I/O 错误时报告失败，已创建的骨架或备份可能保留；重复运行可继续补齐。不得将失败描述为成功或自动回滚。

### 结果与范围

结果包括资源包版本、目标路径、创建与保留清单、原协议版本和内容指纹、协议动作、是否需要用户决定，以及实际备份位置。结构建立、协议升级与知识迁移分别报告，不用前一项成功代替后一项完成。
