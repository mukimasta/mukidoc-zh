# OVERVIEW Design

OVERVIEW 用来让第一次接触项目的人快速建立完整的外部认知。它回答项目是什么、解决什么问题、会交付什么，以及用户实际会怎样使用，但不进入内部设计、架构和实现。

全文结构固定为：

**项目定义 → 解决什么问题 → 交付物 → 用户场景 → 一句话收尾**

开头直接定义项目，不使用小标题。用一小段说明项目是什么、面向谁、核心作用是什么。

**解决什么问题。** 说明项目针对的现实问题和用户困境，回答为什么会需要这个项目。停留在问题层面，不继续追问问题本质或展开设计哲学。建议 1 段。

**交付物。** 明确项目最终向用户提供什么可直接获得、使用或交付的结果。重点描述外部可见的产物，不展开这些产物内部如何实现。内容较多时可以使用简短列表。

**用户场景。** 用一个具体、连续的典型场景描述用户如何实际使用项目。场景应有自然的起点、使用过程和结果，让读者能够直接想象“用了以后会怎样”，而不是重新罗列功能。建议 1 段，必要时可使用 2 个场景。

最后用一句话收尾，从结果角度描述项目能给用户带来的理想状态，“画饼”，聊聊用了这个东西以后，原本困难的事情能够变得多简单、多顺畅或多强大。

全文保持简短，原则上不超过 800 字。一篇好的 OVERVIEW 应让完全不了解项目的人在几分钟内知道：这是什么、为什么值得用、实际怎么用，以及最后能得到什么。
