# Overview

MukiDoc 是为大型项目设计的结构化文档协议。它用结构化的文档保存项目理念、项目架构、项目路线等高层次的项目上下文，以及 Design → System Design → Implementation 三个层级的核心设计链文档。MukiDoc 的协议为这些文档规定了清晰的结构，AI 依据协议掌握项目的全局，并在编写代码的同时维护文档，使其始终保持清晰、优雅和整洁。

**解决什么问题。** AI 让代码越来越容易生成和修改，但项目真正重要的东西——为什么这样设计、系统现在是什么状态、之前做过哪些取舍、某个实现是临时方案还是长期设计——仍然散落在人脑、聊天记录和代码细节里。项目持续越久，个人越容易遗忘当初的判断；团队越大，每个人掌握的信息越不一样；AI 换一个会话，又需要重新解释一遍。现有的记忆系统能让 AI 记住发生过什么，却不能让它掌握项目的全局；没有结构的文档，AI 也很难长期维护好。

**交付物。** MukiDoc 提供方法论与文档规范、可独立使用的 AGENTS.md 工作协议，以及建立固定骨架的初始化 Skill 和脚本。协议随初始化包提供版本，已有项目可选择是否更新。用于检查项目健康度的 MukiCheck 与进一步的迁移、维护工具仍待落地。

**用户场景。** 一个开发者有了新的想法，先自己想清楚它要解决什么问题、应该是什么样，把理念和设计写进上层文档，再和 AI 一起把它细化成系统设计，让 AI 完成代码实现。几周后要做改动，他不必回忆写过哪些类和函数，打开文档确认设计和当初的决定，再告诉 AI 新需求。AI 理解这个改动在全局中的位置，修改代码的同时，把受到影响的文档一起更新到正确的位置。几个月后，新同事或新的 Agent 加入，不需要之前的聊天记录，读项目就能知道这是个什么东西、为什么这样设计、现在做到哪里，以及接下来应该怎样继续。

用了 MukiDoc，项目的理念和方向始终掌握在人手中，项目的知识不再依赖任何人的记忆，而 AI 也能基于完整的全局视角承担越来越多的开发工作。
