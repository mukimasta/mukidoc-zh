# Global View Evaluation

### Claim

拥有项目上层文档（PHILOSOPHY、Design、System Design 与 DECISION）的 AI，比只看到代码和当前对话的 AI 做出更符合项目意图的判断：改动落在正确的层级，不违背已记录的决定，并能把受影响的文档更新到正确位置。

### Scope

System / End-to-End。面向真实或接近真实的项目改动，比较同一模型在有无 MukiDoc 上层文档时的表现。不评价代码风格或单次生成速度。

### Method

选取已采用 MukiDoc 的项目，准备一组需要理解设计意图才能正确完成的改动任务，其中包括会与已记录决定冲突的需求。同一模型分别在两种条件下完成任务：完整 MukiDoc 文档；移除 docs/ 上层文档、只保留代码与必要说明。由 Human 盲评结果。

### Metric / Oracle

1. 改动是否符合 PHILOSOPHY 与 Design 中的意图，是否在冲突时指出与已记录决定的矛盾，而不是静默推翻。
2. 问题是否被定位到正确的层级。
3. 受影响的文档是否被更新到正确位置，没有产生重复或矛盾的描述。

### 当前状态

未验证。目前只有非正式证据：2026-09-15 将 MukiDoc 应用于一个已有项目后，AI 重写的文档明显优于原结构；阿里实习期间一人两个月完成系统时，以这套方法维护上下文。这些说明方法可用，但不能证明 Claim 成立。
