# README Design

README 是项目面向 Human 的仓库入口，用来让第一次打开项目的人快速知道：这是什么、值不值得继续看、怎么开始，以及接下来应该去哪里。

它负责展示和导航，不承担 Project Context 的正式知识保存。README 可以引用或概括项目的重要信息，但真正需要长期维护的内容应存在于对应正式文档中。

README 通常包含：

* 项目名称和一句话价值描述。
* 简短的项目介绍，让读者快速理解它能做什么。
* 必要时提供截图、Demo、示意图等展示内容。
* 项目已经可用时，提供尽可能短的 Quick Start。
* Documentation 入口，引导开发者进入 OVERVIEW、PHILOSOPHY、ARCHITECTURE 等正式文档。
* 项目真正需要的其他对外信息，例如状态、安装、使用、贡献或 License。

README 可以有比其他 MukiDoc 文档更强的展示性，但仍应保持简洁。详细设计、架构、开发历史和方法论内容不应在 README 中重复展开。

README 与 OVERVIEW 的职责不同：README 面向第一次进入仓库的使用者，帮助其快速判断和开始；OVERVIEW 面向准备理解和开发项目的人，负责建立准确的项目认知。

对于已有项目，MukiDoc 不应为了统一格式强行重写一个已经有效的 README。应优先保留原有对外入口，只在必要时整理结构、补充缺失信息和增加 MukiDoc 文档导航。

一篇好的 README 应让陌生人在很短时间内知道：**这是什么、为什么值得看、怎么开始、下一步去哪。**
