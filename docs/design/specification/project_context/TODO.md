# TODO Design

TODO 用来记录项目当前已经确定要做的具体事项，只保留当前行动面。TODO.md 属于固定骨架，即使没有待办也保留文件和标题，不编造任务；完成全部事项后仍保留这个入口。

格式保持简单：

```markdown
# TODO

- [ ] ...
- [ ] ...
- [ ] ...

### Waiting

- [ ] ... — 等待某个前置条件
```

TODO 应满足：

1. 每条都是一个明确、可执行的动作，尽量以动词开头。
2. 默认按优先顺序从上到下排列，不再额外区分 Now / Next。
3. 已确定要做但暂时无法推进的事项放入 `Waiting`。
4. 长期大方向应放入 ROADMAP。
5. 完成后直接删除，不保留历史；已经发生的事情由 DEVLOG 记录。
6. 保持简短，不在 TODO 中展开背景、设计和讨论。

一篇好的 TODO 应该让任何时候进入项目的人，不必翻代码和历史，就能立刻知道项目接下来最该做什么。
